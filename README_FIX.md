# Исправление проблемы со статусом SIM-карт

## Проблема
Дашборд показывает:
- Всего терминалов: 5
- Свободно терминалов: 5
- Всего SIM-карт: 1
- Свободно SIM: 0

Это невозможно, так как SIM-карта не может быть в аренде без терминала.

## Причина
Статус SIM-карты (`tblsimcards.status`) не синхронизировался со статусом терминала. Возможные причины:
1. Ручное изменение данных в БД
2. Ошибки при возврате терминалов
3. Замена SIM-карты в терминале без обновления статуса старой SIM

## Исправления в коде

### 1. `mainwindow.cpp` - Исправлен запрос для подсчета свободных SIM
```sql
-- Старый запрос (неправильный):
SELECT COUNT(*) FROM tblsimcards WHERE status = 0

-- Новый запрос (правильный):
SELECT COUNT(*) FROM tblsimcards s
WHERE s.status = 0
OR EXISTS (
    SELECT 1 FROM tblterminals t
    WHERE t.currentsimcardid = s.simcardid
    AND t.status = 0
)
```

### 2. `returnform.cpp` - Исправлен сброс статуса SIM при возврате
Теперь статус SIM-карты сбрасывается на основе актуального значения `currentsimcardid` из таблицы терминалов, а не из истории аренды.

### 3. `rentalform.cpp` - Обновлен запрос для загрузки свободных SIM
```sql
-- Новый запрос учитывает SIM-карты, которые могут быть привязаны к возвращенным терминалам
```

## Как работает исправление

### При возврате терминала:
1. Терминалу устанавливается `status = 0` и `currentsimcardid = NULL`
2. Статус SIM-карты сбрасывается на основе актуального `currentsimcardid`
3. Если SIM была привязана, её статус также сбрасывается на 0

### При аренде терминала:
1. Терминалу устанавливается `status = 1` и `currentsimcardid = simid`
2. Статус SIM-карты устанавливается на 1 (в аренде)

### При подсчете свободных SIM:
- Считаются SIM-карты со статусом 0
- Считаются SIM-карты, привязанные к терминалам со статусом 0

## Триггер защиты

После добавления триггера `trg_sync_sim_status` при обновлении терминала (изменении статуса с 1 на 0) будет автоматически сбрасываться статус привязанной SIM-карты.
