# План реализации замечаний по проекту POC Terminal Tracker

## Обзор
Замечания разделены на 6 задач, каждая из которых реализована в соответствии с логикой и структурой текущего проекта (Qt6 + PostgreSQL, QSqlTableModel,_dialog-based_ формы).

---

## Задача 1. PostgreSQL последовательности и функция `generate_doc_number`

### Цель
Заменить `QDateTime::currentMSecsSinceEpoch()` на надёжную генерацию номеров через PostgreSQL sequences.

### SQL-скрипт `sql/doc_sequences.sql`
- `seq_receipt_doc_number` — поступление (формат: `ПП-00001`)
- `seq_rental_doc_number` — аренда (формат: `АР-00001`)
- `seq_return_doc_number` — возврат (формат: `ВР-00001`)
- `seq_payment_doc_number` — оплата (формат: `ОП-00001`)
- Функция `generate_doc_number(p_prefix text)` — возвращает номер с префиксом и автоматическим инкрементом

### Код
- `ReceiptForm::generateDocNumber()` — вызывает `generate_doc_number('ПП')`
- `RentalForm::generateDocNumber()` — вызывает `generate_doc_number('АР')`
- `ReturnForm::generateDocNumber()` — вызывает `generate_doc_number('ВР')`
- `PaymentForm` — аналогично для `ОП` (если нужна)

## Задача 2. Валидация данных

### Цель
Добавить проверку перед сохранением данных в формах CRUD и документов.

### IMEI (15 цифр)
- `receiptform.cpp`: проверка `imei1` и `imei2` — строго 15 цифр
- `terminalsform.cpp`: аналогичная проверка при добавлении/редактировании терминала
- `QRegularExpressionValidator` в UI для полей IMEI

### Серийный номер
- Проверка на непустое значение
- Уникальность (проверка через `SELECT COUNT(*) FROM tblterminals WHERE serialnumber = :sn`)

### ИНН клиента
- Проверка длины: 10 или 12 цифр
- Только цифры
- `QRegularExpressionValidator` в `clientsform.cpp`

### Реализация
- Создать утилитарный класс `Utils::Validator` с статическими методами:
  - `bool validateIMEI(const QString& imei)`
  - `bool validateINN(const QString& inn)`
  - `bool validateSerialNotEmpty(const QString& serial)`
  - `bool checkUniqueSerial(const QString& serial)`
- Интегрировать валидаторы в формы

## Задача 3. Поиск в справочниках (live filter)

### Цель
Добавить строку поиска над таблицей в каждой CRUD-форме для фильтрации записей на лету.

### Формы для улучшения
- `ClientsForm` — поиск по имени, ИНН
- `ManufacturersForm` — поиск по названию
- `ModelsForm` — поиск по названию модели
- `SIMCardsForm` — поиск по номеру SIM
- `TerminalsForm` — поиск по серийному номеру, IMEI
- `ArchiveDocumentsForm` — усиление существующего фильтра

### Реализация
- Добавить `QLineEdit` (id: `lineEditSearch`) над таблицей в каждой форме
- Слот `on_lineEditSearch_textChanged(const QString&)`
- Использование `QSqlTableModel::setFilter()`:
  - `model->setFilter("clientname LIKE '%text%' OR inn LIKE '%text%'")`
- Дебаунс: `QTimer` с задержкой 300мс для уменьшения запросов к БД
- При пустом поиске — сброс фильтра (`model->setFilter("")`)

## Задача 4. Логирование действий пользователя

### Цель
Вести аудит: кто, когда и какое действие выполнил (создание/редактирование/удаление документов).

### SQL-скрипт `sql/audit_log.sql`
- Таблица `tbl_audit_log`:
  - `audit_log_id` (SERIAL PRIMARY KEY)
  - `user_id` (INTEGER, FK → tbl_users, NULL для системных действий)
  - `action` (VARCHAR(50)) — CREATE, UPDATE, DELETE, POST
  - `table_name` (VARCHAR(50))
  - `record_id` (INTEGER)
  - `old_values` (JSONB, nullable)
  - `new_values` (JSONB, nullable)
  - `performed_at` (TIMESTAMP DEFAULT NOW())
  - `username` (VARCHAR(100)) — имя пользователя (human-readable)

- Таблица `tbl_users`:
  - `user_id` (SERIAL PRIMARY KEY)
  - `username` (VARCHAR(100) UNIQUE)
  - `display_name` (VARCHAR(100))
  - `is_active` (BOOLEAN DEFAULT true)

### Реализация
- `DatabaseManager::logAction()` — статический метод для записи в аудит
- Вызов `logAction()` в каждом `on_btnPost_clicked()`:
  - table_name: "tblrentaldocs", action: "POST", record_id: docId
- Минимальная информация: `username` (пока hardcoded "admin"), timestamp, действие

## Задача 5. Обработка ошибок `model->select()`

### Цель
Усилить обработку ошибок в формах, где `model->select()` может завершиться неудачно.

### Формы с улучшениями
- `ClientsForm` — текущий код уже проверяет `select()`, усилить retry-логику
- `ManufacturersForm` — добавить проверку и retry
- `ModelsForm` — аналогично
- `SIMCardsForm` — аналогично
- `TerminalsForm` — аналогично
- `ArchiveDocumentsForm` — улучшить обработку ошибок при фильтрации

### Реализация
- Шаблоны try-catch для `select()`:
  ```cpp
  if (!model->select()) {
      QMessageBox::critical(this, "Ошибка БД",
          "Не удалось загрузить данные: " + model->lastError().text() +
          "\n\nПроверьте соединение с базой данных.");
      return;
  }
  ```
- Retry-логика: 3 попытки с задержкой 500мс
- Отключение UI-элементов при ошибке загрузки
