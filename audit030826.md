## 1. Архитектура и код

### ✅ Сильные стороны
- **Многопользовательская конкурентность** — блокировки `FOR UPDATE NOWAIT`, advisory locks для миграций, атомарные UPDATE для rate limiting. Тесты `test_concurrency` это подтверждают.
- **Circuit Breaker** — защита от каскадных сбоев БД, состояниями Closed/Open/HalfOpen.
- **Connection Pooling** — per-thread пул соединений для фоновых операций (BackupWorker).
- **Миграции БД** — транзакционные, с advisory lock от гонок, идемпотентные.
- **Фоновый бэкап** — `BackupWorker` в отдельном потоке, не блокирует UI.
- **Шифрование бэкапов** — AES-256-CBC с маркером `POCENC1`, обратная совместимость.
- **Health-check CLI** — `--check-db`, `--version`, `--help`.
- **Graceful shutdown** — `aboutToQuit` закрывает БД.
- **Certificate pinning** — SPKI SHA-256 для автообновлений.
- **SHA256-верификация** обновлений при скачивании.
- **Пагинация** в `TerminalsForm` (LIMIT/OFFSET).
- **Интерфейс `IDatabaseManager`** — корректная подмена в тестах (без moc-хаков).
- **HTTPS обязателен для автообновлений** — `isSecureUpdateUrl()` (http только для localhost).
- **SSL по умолчанию `require`** — защита от MITM.
- **CMake-проверка утилит** — предупреждения при отсутствии `pg_dump`/`psql`/`openssl`.
- **QXlsx docs** — версия зафиксирована в `docs/OPS.md`.

## 2. Безопасность

### ✅ Хорошее
- PBKDF2-HMAC-SHA256 с 100k итераций
- Constant-time сравнение хешей
- Rate limiting на уровне БД
- SQL-инъекции устранены (форматирование через `QSqlField::formatValue`)
- SSL с проверкой сертификата (при настройке)
- Certificate pinning для обновлений
- AES-256-CBC шифрование бэкапов
- Ролевая защита на уровне БД (триггеры)
- Аудит действий пользователей
- **HTTPS обязателен для автообновлений** — `isSecureUpdateUrl()`
- **SSL по умолчанию `require`** — защита от MITM
- **Предупреждение о пустом пароле БД** при старте

### ⚠️ Требует внимания
- **Хардкод пароля в 001_initial.sql** — критично для первой установки
- **Пароли бэкапов** — передаются как аргументы/env var, могут быть видны в `/proc`. Шифрование отделено от пароля БД (`backup.passphrase`, `cbac0dd`), но сам ключ по-прежнему передаётся `openssl` через аргумент.
- **Нет двухфакторной аутентификации** — для admin-учёток рекомендуется
