# ADR-0001 — Архитектура доступа к базе данных

**Статус:** принято
**Дата:** 03.08.2026

## Контекст
Приложение работает с PostgreSQL из GUI-потока и из фоновых потоков (бэкап),
поддерживает несколько одновременных экземпляров и требует аудита всех изменений.

## Решение
- **Один синглтон `DatabaseManager`** (интерфейс `IDatabaseManager`), через который
  проходят все операции с БД. Тесты используют заглушку через глобальную `databaseManager()`.
- **Миграции** — файлы `sql/migrations/NNN_*.sql` с `pg_advisory_lock` для защиты от гонки
  при одновременном старте нескольких экземпляров.
- **Аудит** — триггеры в БД (таблица `tbl_audit_log`), контекст сессии через `set_config`.
- **Межэкземплярное обновление** — `NOTIFY poc_data_changed`, подписка в `listenForDataChanges()`.
- **Транзакции** — `executeTransaction()` с автоматическим повтором transient-ошибок
  (SQLSTATE 08*, 40P01, 40001, 57P01; до 3 попыток) и circuit breaker для fail-fast.

## Следствия
- Валидация полей дублируется и на уровне UI, и на уровне БД (CHECK-ограничения, триггеры).
- Соединение главного потока не используется в рабочих потоках — для них `ConnectionPool` (ADR-0003).

# ADR-0002 — Хранение и проверка паролей

**Статус:** принято
**Дата:** 03.08.2026

## Контекст
Пароли пользователей хранятся в БД; требуется устойчивость к перебору и принудительная
смена устаревших (legacy) хешей.

## Решение
- **PBKDF2-HMAC-SHA256, 100 000 итераций**, соль 16 байт. Формат хеша `iter:salt:hash` (hex).
- **Constant-time сравнение** (`QByteArray::operator==` после нормализации через
  `std::equal`-подобный проход — см. `password_utils.cpp`).
- **`isLegacyPasswordHash()`**: любой хеш, не соответствующий формату `iter:salt:hash`,
  помечается как требующий смены при следующем входе (`must_change_password`).
- **Rate limiting**: 5 неудачных попыток → блокировка 30 с (атомарный UPDATE в БД).

## Следствия
- Дефолтный пароль администратора из миграции 001 обязан быть сменён при первом входе —
  механика принудительной смены описана в OPS.md.
- Функция `validatePasswordStrength()` (мин. 8 символов, заглавная буква, цифра) применяется
  при регистрации и смене пароля.

# ADR-0003 — Фоновый бэкап и пул соединений

**Статус:** принято
**Дата:** 03.08.2026

## Контекст
pg_dump/psql блокировали UI-поток через `QProcess::waitForFinished`; фоновые потоки
создавали соединения на каждый вызов, что при многих пользователях нагружает PostgreSQL.

## Решение
- **`BackupWorker`** — операции бэкапа/восстановления вынесены в отдельный `QThread`
  с собственным соединением из `ConnectionPool`; результат сообщается сигналами.
- **`ConnectionPool`** — per-thread пул (`acquire()/release()`, ожидание при превышении лимита),
  уникальные имена соединений (`QUuid`).
- **Шифрование бэкапов** — при заданном пароле файл шифруется AES-256-CBC
  (`openssl enc -aes-256-cbc -pbkdf2 -iter 100000`), маркер `POCENC1\n` в начале файла;
  plain-файлы без маркера восстанавливаются как раньше (обратная совместимость).

## Следствия
- Ручной и автоматический бэкапы асинхронны; пользователь видит статус в строке состояния.
- Пароль для шифрования не сохраняется на диск.

# ADR-0004 — Модели, делегаты и конвенция ComboBoxDelegate

**Статус:** принято
**Дата:** 03.08.2026

## Контекст
UI построен на Model/View. Для справочных значений (статусы, модели, SIM) используется
`ComboBoxDelegate`; аудит выявил риск путаницы при чтении ролей.

## Решение
- **Конвенция**: для колонок с выбором значения `Qt::UserRole` = числовой ID (машинное
  значение, используется при сохранении), `Qt::DisplayRole` = человекочитаемый текст
  (то, что видит пользователь). Это осознанное соглашение, закреплённое тестом
  `test_ui_components::comboboxDelegateWritesUserAndDisplayRoles`.
- `CheckBoxDelegate`/`ReadOnlyDelegate` — специализированные делегаты для своих случаев.
- `ComboBoxModel` безопасен для невалидных индексов (проверка `index.isValid()`
  предотвращает краш `QList::at` out-of-range).

## Следствия
- Код, читающий значение колонки с делегатом, должен использовать `Qt::UserRole`.
- Новые делегаты обязаны соблюдать эту конвенцию.

# ADR-0005 — Доставка, подпись и обновления

**Статус:** принято
**Дата:** 03.08.2026

## Контекст
Продукт поставляется на Windows (портативный ZIP + NSIS-инсталлятор), собирается и на Linux (CI).

## Решение
- **Доставка**: цель `deploy` (windeployqt) + CPack ZIP/NSIS; версия берётся из `config.json`.
  Если `windeployqt` не найден — configure завершается ошибкой (явный отказ вместо тихого пропуска).
- **Подпись**: опционально — `osslsigncode` (локально) или `Set-AuthenticodeSignature` (CI),
  секреты `CODE_SIGN_PFX_BASE64`/`CODE_SIGN_PASSWORD`.
- **Обновления**: проверка манифеста при старте; `sha256` из манифеста + SPKI-пиннинг
  (`update.pinned_sha256`) защищают от MITM.
- **Версионирование**: авто-bump patch в `config.json` + авто-changelog в CI при push в master.

## Следствия
- Локальная сборка требует Qt в `CMAKE_PREFIX_PATH` (windeployqt обязателен для deploy-цели).
- Контрольные суммы `.sha256` генерируются для каждого артефакта.
